## Главное

Версия 3.5.6 заменяет сложный конструктор секций в повседневной работе на обычный классический редактор, похожий по логике на старый редактор WordPress. Конструктор не удалён: он остаётся дополнительным режимом для сложных посадочных страниц.

## Классический редактор

- единое поле для набора и оформления текста;
- вкладки «Визуально» и «Текст»;
- абзацы и заголовки H2–H4;
- жирный, курсив, подчёркивание и зачёркивание;
- маркированные и нумерованные списки;
- цитаты и горизонтальная линия;
- выравнивание текста;
- вставка и удаление ссылок;
- отмена и повтор действия;
- полноэкранный режим;
- счётчик слов и знаков;
- горячие клавиши Ctrl/Cmd+B, I, U, K и S;
- вставка изображений непосредственно из медиатеки;
- предпросмотр до сохранения;
- серверное и клиентское автосохранение;
- история ревизий сохраняется.

## Безопасность содержимого

Классический редактор не сохраняет произвольный опасный HTML. Перед записью сервер:

- удаляет script, iframe, object, form и другие опасные элементы;
- удаляет inline-обработчики событий;
- запрещает javascript:, data: и другие опасные URL;
- оставляет разрешённое форматирование, таблицы, ссылки и изображения;
- добавляет безопасные атрибуты внешним ссылкам и изображениям.

## Демонстрационный сайт

В разделе **Studio → Пресеты и демо** появилась команда создания демонстрационного сайта KOVCHEG CMS. Она создаёт только отсутствующие данные:

- рубрики «Новости», «Разработка» и «Документация»;
- страницы «О проекте», «Возможности» и «Контакты»;
- публикацию о релизе 3.5.6;
- главное меню;
- стартовые описания и оформление KOVCHEG Portal.

Существующие публикации и пользователи не удаляются и не перезаписываются. Поисковая индексация после установки демо остаётся выключенной до замены тестового содержания.

## Совместимость

- старые материалы продолжают отображаться через сохранённый `content_html`;
- конструктор секций доступен отдельной вкладкой;
- база данных и новые миграции для релиза не требуются;
- PHP 8.1+, рекомендуется PHP 8.3.

## Проверки

```bash
php scripts/audit-classic-editor.php
node --check assets/js/blog-classic-editor.js
```

Отдельный GitHub Actions workflow проверяет PHP, JavaScript, серверную очистку HTML, подключение assets и регистрацию демо-маршрута.
