## Секреты и пользовательские данные

Никогда не публикуйте в Git:

- `config/config.php`;
- `.env` и локальные файлы окружения;
- пароли и API-ключи;
- приватные ключи;
- дампы базы данных;
- содержимое `storage/uploads`;
- журналы `storage/logs`;
- резервные копии;
- пользовательские документы и персональные данные.

В репозитории используется `.gitignore`, а CI дополнительно проверяет отсутствие типичных секретов и runtime-данных.

## Production

Для рабочей установки обязательны:

- HTTPS;
- актуальная поддерживаемая версия PHP;
- закрытый прямой веб-доступ к `config`, `database`, `storage`, `app`, `routes`, `views`, `docs` и служебным каталогам;
- уникальный application key не короче 32 байт;
- минимально необходимые права файловой системы;
- регулярная резервная копия базы и `storage/uploads`;
- проверка резервного восстановления;
- обновление только после успешного CI.

## Защита приложения

KOVCHEG CMS использует:

- CSRF-токены для изменяющих запросов;
- Content Security Policy;
- HSTS при HTTPS;
- `X-Content-Type-Options: nosniff`;
- `X-Frame-Options: SAMEORIGIN`;
- Referrer Policy, COOP и CORP;
- HttpOnly и SameSite cookies;
- регенерацию session ID после успешного входа;
- ограниченный срок основной сессии;
- безопасное хеширование паролей;
- PDO prepared statements без эмуляции;
- проверку MIME и размера загружаемых файлов;
- перекодирование загружаемых изображений;
- серверную проверку ролей и прав;
- журналирование административных действий.

## Модули

Установка серверного модуля с PHP-кодом является доверенной административной операцией. ZIP-пакет нельзя устанавливать из неизвестного источника. Перед установкой должны быть проверены код, manifest, SQL и состав архива.

## Сообщение об уязвимости

О найденной уязвимости сообщайте правообладателю приватно. Не публикуйте:

- рабочие ключи;
- реальные данные пользователей;
- дампы production;
- готовый пошаговый способ эксплуатации до выпуска исправления.

При исправлении критической уязвимости сначала создаётся резервная копия, затем отдельная ветка, проверка, Pull Request и контролируемый production-deploy.
