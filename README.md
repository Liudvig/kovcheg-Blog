# KOVCHEG Blog / KOVCHEG CMS 3.9

**KOVCHEG Blog** — самостоятельный блоговый движок и система управления сайтом KOVCHEG CMS.

Автор и правообладатель: **Ланцет Семён Борисович**.  
Лицензия: **proprietary / all rights reserved**.

## Назначение

KOVCHEG Blog предназначен для обычного информационного сайта, новостного проекта, авторского блога, сайта организации или профессионального портала.

Базовая модель содержимого intentionally проста:

- **Записи** — новости, статьи и публикации;
- **Рубрики** — тематические разделы Записей;
- **Страницы** — постоянные разделы сайта;
- **Медиафайлы** — изображения и другие разрешённые файлы;
- **Меню** — несколько независимых меню;
- **Виджеты и зоны** — управляемые блоки сайта;
- **Пользователи** — роли и доступ;
- **Брендинг и темы** — логотип, favicon, цвет, оформление;
- **Настройки** — параметры публикации, регистрации и сайта.

Отдельный обязательный раздел с названием «Блог» не создаётся. Владелец сам определяет структуру сайта через рубрики, страницы и меню.

## KOVCHEG Studio

Основной административный интерфейс расположен по адресу `/studio`.

Разделы Studio:

```text
Обзор
Записи
Рубрики
Страницы
Комментарии
Медиафайлы
Меню
Виджеты и зоны
Брендинг и тема
Пользователи
Настройки
```

Записи и Страницы редактируются единым классическим визуальным редактором. Поддерживаются:

- визуальный режим и HTML;
- изображения из медиатеки;
- обложка материала;
- автосохранение;
- ревизии;
- предпросмотр;
- черновики;
- публикация по расписанию;
- приватная видимость;
- SEO-заголовок и описание.

## Публичные маршруты

```text
/                    главная
/post/{slug}         запись
/page/{slug}         страница
/category/{slug}     рубрика
/author/{username}   публикации автора
/search              поиск
/login               вход
/register            регистрация, если разрешена
/account             личный кабинет
/robots.txt          правила индексации
/sitemap.xml         карта сайта
/feed.xml             RSS
```

Старые адреса ранних версий могут обслуживаться только как совместимые переходы и не являются частью текущей модели содержимого.

## Темы и компоновка

В поставку входят собственные темы KOVCHEG. Тема отвечает за внешний вид, а содержимое и бизнес-логика остаются в ядре CMS.

Layout & Widget Engine поддерживает:

- шапку;
- левую колонку;
- центральную область;
- правую колонку;
- подвал;
- дополнительные полосы над и под содержимым.

Виджет можно создать, настроить, включить, отключить, скопировать, переместить или убрать из публичной схемы.

## Меню

Можно создавать несколько независимых меню. Пункты меню формируются из:

- Страниц;
- Рубрик;
- произвольных URL.

Меню можно назначить в шапку, боковую колонку или подвал, а также разместить как виджет.

## Безопасность

Основные механизмы защиты:

- CSRF-защита изменяющих запросов;
- Content Security Policy;
- HSTS при HTTPS;
- `X-Content-Type-Options`, `X-Frame-Options`, COOP/CORP;
- HttpOnly и SameSite cookies;
- смена session ID после входа;
- Argon2id для новых/обновляемых паролей при доступности;
- PDO prepared statements без эмуляции;
- проверка MIME загружаемых файлов;
- ограничение размера загрузок;
- безопасная обработка изображений;
- аудит административных действий;
- автоматические CI-проверки секретов и runtime-данных.

Подробности: [`SECURITY.md`](SECURITY.md).

## Требования

- PHP 8.1+, рекомендуется PHP 8.3;
- MySQL 8 или MariaDB 10.6+;
- PDO MySQL;
- mbstring;
- fileinfo;
- OpenSSL;
- GD или Imagick для обработки изображений;
- HTTPS для production.

## Установка и обновление

Runtime-конфигурация хранится в `config/config.php` и **не должна попадать в Git**.

Обновление базы:

```bash
php bin/migrate.php
```

Перед production-обновлением обязательно сохранить:

- базу данных;
- `storage/uploads`;
- `config/config.php`;
- текущий commit production.

Обновление кода выполняется только fast-forward после успешного CI:

```bash
git fetch origin main
git merge --ff-only origin/main
php bin/migrate.php
```

## Разработка

Рабочий процесс проекта:

```text
feature branch
→ реализация
→ PHP/JS lint
→ продуктовые аудиты
→ MariaDB/MySQL migrations check
→ HTTP smoke tests
→ Pull Request
→ merge в main
→ резервная копия production
→ deploy
→ production verification
```

Архитектуру ядра не переписывают без необходимости. Новая функция должна использовать текущие KOVCHEG-компоненты, права, маршрутизатор, медиатеку и систему виджетов.
